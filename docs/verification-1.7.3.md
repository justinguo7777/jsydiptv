# jsydiptv 1.7.3 候选验收与拉取审查

以 NAS 已验的 1.8.2 测试代码为基线，保留 HLS 回调修复、两套清单和现有订阅协议；1.7.3 是接在公开 1.7.2 之后的版本号，本次仅包装。

## 视觉与交互

- 冷灰色页面、纯色待播底、微透明圆角面板；移除光带和多色渐变，保留浅深色及减少透明度。网页 LOGO 在打包时从 FPK 的 `ICON_256.PNG` 共源复制，避免两套图标漂移。
- 参考 [IPTVnator](https://github.com/4gray/iptvnator#features) 的统一频道目录与收藏：保留筛选中的搜索，`/` 聚焦、Enter 播放首个过滤结果、Esc 清空；收藏和选台仍是分离的操作。
- 参考 [Kodi PVR](https://kodi.wiki/view/PVR) 的当前节目定位：展示当前与下一节目，切去其他日期或「只看可回看」后可回到今天的当前节目。未来节目只展示，已播且满足回看窗口的才可点击回看。

## 拉取链路审查

| 范围 | 发现及影响 | 本次改动 / 后续 |
|---|---|---|
| 上游参数、地市与分组 | 活跃路径使用运营商能力参数和 UA；13 市并集、地方台交叉识别具有必要性。保留现有分组兜底，不把历史 `upstream/` 归档当运行代码。 | 不修改运营商契约，不增加全自动发现。现有地市串行耗时和部分失败的可见性仍有改善空间。 |
| EPG 拉取与原子发布 | 异常行可能使工作线程失败；失败响应可能被当作空节目单，导致缺页的新一代覆盖旧数据。 | 校验响应结构和状态码，编码 UUID，跳过坏记录并去重；12 秒单次超时、一次重试；每批至少 10 个请求且失败超过 40% 则拒绝更新。与上一代的同频道比较，基线至少 10 台且保留不足 60% 则拒绝发布。空代检查仍保留；未声称验证了逐日覆盖。 |
| CDN 选源 | 分组样本和随机样本重叠，导致结果虚高或重复请求。 | 去重后抽检。仍以有效 HLS 清单为健康信号，不能据此认定所有切片及回看都能播放；后续可补抽样解码与回看可用性检查。 |
| 拉流和媒体探测 | 超时可能在媒体响应体后写入另一条错误响应；清单读取未设上限，前缀被当成全量估码率。 | 响应未开始时返回 502，开始后截断并关连接；清单读取限 1 MiB；探测样本有界，前缀不报整段码率；不将主清单变体误当切片。主清单选档探测未实现，探测缺失仍标记待探测。 |
| 启动、配置及前端刷新 | 首装等首次抓取才监听；网络超时误报解码；已有目录刷新失败时无提示。 | 先绑定 HTTP 端口，首次更新转后台；播放超时显示重试，旧目录显示未刷新提示。手动更新 API 暂保留同步语义以兼容客户端，队列化与全任务截止时间未做。 |
| 台标、反代及访问边界 | 台标本地化沿用原逻辑；反代生成清单的地址受请求 Host 影响。管理接口应用层鉴权和逐跳取流目标校验未覆盖。 | 保持现有行为，不以本次包作为公网开放版本。若需暴露到非受信网络，应另做鉴权、GET 写操作迁移、反代显式基址和逐跳校验。 |

## 验证边界

源码离线回归 8 项通过；解包合成数据 168 项接口、19 项只读网页检查、15 组浏览器交互/布局通过，含 LOGO 加载、键盘选台、节目单跳转、窄窗口及播放器回归。真实上游、飞牛桌面登录后的入口与终端播放需要对本包另验；1.8.2 的真机记录不能替代。产物及构建指纹在 `dist/1.7.3/`，本次不部署、不推送、不发布。
